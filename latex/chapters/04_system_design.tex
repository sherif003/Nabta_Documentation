\section{Overview}
\label{sec:design_overview}

This chapter presents the complete architectural specification of the \nabta system. The design is decomposed across three primary layers---frontend, backend, and AI/database---and documented through architectural diagrams, component descriptions, database schema specifications, and API endpoint definitions. The overarching design philosophy prioritises modularity, enabling independent evolution of individual components; performance, particularly sub-second inference latency; and security, through defence-in-depth mechanisms at every layer.

\section{Frontend Design}
\label{sec:frontend_design}

\subsection{Technology Stack}
\label{subsec:fe_stack}

The \nabta frontend is implemented as a single-page application (\gls{spa}) using \textbf{React.js} with functional components and the React Hooks API. State management is handled through a combination of component-local \code{useState}/\code{useReducer} hooks and a lightweight context-based global store for authenticated user state. HTTP communication with the backend is handled via the \textbf{Axios} library with request interceptors that inject the Firebase \gls{jwt} authentication token into the \code{Authorization} header of every protected request.

\subsection{Key Interface Screens}
\label{subsec:fe_screens}

\subsubsection{Main Analysis Dashboard}
\label{subsubsec:main_dashboard}

The primary user interface screen presents a drag-and-drop image upload widget supporting \texttt{.jpg} and \texttt{.png} files up to 5MB. Upon successful upload, the interface transitions to a three-panel results layout:

\begin{itemize}[leftmargin=*]
  \item \textbf{Detection Panel:} Renders the uploaded image with bounding box overlays indicating the detected infected leaf regions, annotated with the YOLOv8 confidence score.
  \item \textbf{Classification + Grad-CAM Panel:} Displays the predicted plant species, disease name, and confidence percentage alongside the Grad-CAM heatmap overlay image.
  \item \textbf{Segmentation Panel:} Renders the binary segmentation mask with the leaf foreground highlighted in the system's primary colour.
\end{itemize}

\section{Backend Design}
\label{sec:backend_design}

\subsection{Technology Stack}
\label{subsec:be_stack}

The backend is implemented in \textbf{Python 3.11} using the \textbf{FastAPI} framework~\cite{fastapi2023}. FastAPI was selected for its native support for asynchronous request handling via Python's \code{asyncio} runtime, its automatic OpenAPI schema generation, and its high throughput benchmarks relative to synchronous WSGI alternatives. Serving is managed by a \textbf{Uvicorn} ASGI server, with \textbf{Gunicorn} as the process manager for multi-worker production deployments.

\subsection{Image Preprocessing Module}
\label{subsec:preproc_module}

The \code{ImageProcessor} class encapsulates all preprocessing logic applied to incoming images prior to model inference. Upon receiving a multipart upload, the module:

\begin{enumerate}[leftmargin=*, label=\arabic*.]
  \item Decodes the binary payload using \code{Pillow} and validates the MIME type and file size.
  \item Resizes the image to the required resolution for each model stage using Lanczos resampling.
  \item Converts to a normalised \code{NumPy} array and constructs a batched \code{PyTorch} tensor.
  \item Returns separate tensor copies prepared for YOLOv8 (640px), U-Net (256px), and CNN (224px) input dimensions.
\end{enumerate}

\subsection{ML Pipeline Router (MLManager)}
\label{subsec:mlmanager}

The \code{MLManager} class implements the sequential orchestration logic connecting the three inference models. Each model is loaded into GPU memory at server startup using a singleton pattern to eliminate per-request loading overhead. The sequential dispatch proceeds as follows:

\begin{enumerate}[leftmargin=*, label=\textbf{Step \arabic*.}]
  \item \textbf{Detection:} The 640px tensor is passed to the YOLOv8 engine. If no bounding box exceeds the confidence threshold ($\geq 0.25$), an early-exit response is returned.
  \item \textbf{ROI Crop:} The highest-confidence bounding box coordinates are used to crop the original image. If multiple boxes are returned, the largest-area box is selected.
  \item \textbf{Segmentation:} The cropped image is resized to 256px and passed to the U-Net engine, returning a binary probability mask. The mask is thresholded at 0.5 and applied to the crop.
  \item \textbf{Classification:} The masked crop is resized to 224px and passed to the CNN classifier, yielding the softmax probability distribution across 102 classes.
  \item \textbf{Grad-CAM:} Gradients are computed with respect to the final convolutional layer of the CNN for the predicted class, and the heatmap is composited onto the 224px crop.
  \item \textbf{Result Assembly:} A \code{PredictionResult} object is constructed and serialised to JSON.
\end{enumerate}

\label{subsec:vector_db}

\section{Security Architecture}
\label{sec:security}

The \nabta security posture is implemented through a defence-in-depth strategy comprising multiple independent layers:

\subsection{Authentication and Authorisation}
\label{subsec:auth_sec}

All user identity management is delegated to \textbf{Firebase Authentication}, which provides industry-standard OAuth 2.0 flows, encrypted credential storage, and brute-force protection. Upon successful authentication, Firebase issues a signed \gls{jwt} with a one-hour expiry. This token is transmitted in the \code{Authorization: Bearer} header of all API requests and verified by the FastAPI middleware layer using the Firebase Admin SDK before any protected handler is invoked.

\subsection{Transport Security}
\label{subsec:transport_sec}

All client-server communication is mandated to occur over \textbf{HTTPS} with TLS 1.2 or higher. HTTP-to-HTTPS redirection is enforced at the reverse proxy layer (Nginx). \gls{hsts} headers are set to prevent protocol downgrade attacks.

\subsection{API Key Management}
\label{subsec:key_sec}

Third-party API keys (Cohere API key, Firebase service account credentials) are stored exclusively as environment variables injected at deployment time. No API keys are committed to version control or transmitted to the frontend. The \code{python-dotenv} library is used for local development environment management.

\subsection{Input Validation}
\label{subsec:input_sec}

All incoming file uploads are validated for MIME type, file extension, and size before processing. Pydantic model validation enforces strict schema conformance on all JSON request bodies, rejecting malformed or unexpected fields with structured error responses.
